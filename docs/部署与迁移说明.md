# 部署与迁移说明

## 目标

当前仓库已经收敛为一套可迁移的运行结构：

- `OpenClaw` 使用官方成品安装，运行在宿主机
- `FISCO BCOS` 使用仓库内打包的运行资产，通过 Docker 启动
- `FastAPI + 虚拟 App + 演示端` 运行在宿主机

这意味着迁移时不需要再依赖当前机器上的 `/home/chelizi/fisco` 目录。

## 已纳入仓库的运行资产

### FISCO BCOS

- 链运行目录: `runtime-deps/fisco-portable`
- 链节点配置: `runtime-deps/fisco-portable/nodes/127.0.0.1`
- SDK 证书: `runtime-deps/fisco-portable/nodes/127.0.0.1/sdk`
- Console: `runtime-deps/fisco-portable/console`
- Java SDK 源码: `runtime-deps/java-sdk`
- 本地 JDK 11: `runtime-deps/jdks/temurin-11`
- Docker 镜像归档: `runtime-deps/images/fiscobcos-v3.6.0-image.tar`

当前体积大致为：

- `runtime-deps/fisco-portable`: 约 `151M`
- `runtime-deps/images/fiscobcos-v3.6.0-image.tar`: 约 `33M`

### OpenClaw

`OpenClaw` 没有被打包进仓库。它按最终方案作为外部官方成品使用，因此迁移时需要在目标机器单独安装。

为了减少重新联网拉包的次数，仓库里额外缓存了一份 npm 包归档：

- `runtime-deps/packages/openclaw-2026.4.5.tgz`

官方安装文档：

- https://docs.openclaw.ai/install
- https://docs.openclaw.ai/start/setup

## 启动方式

### 1. 启动 FISCO BCOS

仓库根目录执行：

```bash
./scripts/fisco-up.sh
```

脚本会做两件事：

1. 如果本地还没有 `fiscoorg/fiscobcos:v3.6.0` 镜像，就自动从仓库内的镜像归档导入
2. 使用仓库内的链配置启动 4 个节点

检查状态：

```bash
./scripts/fisco-status.sh
```

停止：

```bash
./scripts/fisco-down.sh
```

进入 Console：

```bash
./scripts/fisco-console.sh
```

### 2. 检查 OpenClaw

```bash
./scripts/openclaw-check.sh
```

如果没有安装 `OpenClaw`，按官方文档安装后再执行。

### 3. 启动项目服务

后续主工程统一按照仓库内代码运行：

- `FastAPI` 网关
- 虚拟 `App`
- 演示端

这些服务不依赖 `/home/chelizi/fisco`，只依赖仓库内的 FISCO 目录和 Docker。

如果你想一键拉起整套本地演示环境，可以直接在仓库根目录执行：

```bash
./scripts/openq-up.sh
./scripts/openq-down.sh
```

这个脚本会先检查或启动 FISCO BCOS，再检查或拉起 OpenClaw gateway，最后启动 `FastAPI` 演示端。脚本确认服务可用后会直接退出，三个服务会继续在后台运行。
如果你要关停整套演示环境，可以执行 `./scripts/openq-down.sh`，它会优先按 PID 文件和进程特征清理本仓库启动的服务。

## 迁移到新机器

## Ubuntu

推荐方式：

1. 安装 `Docker Desktop` 或 `Docker Engine`
2. 安装 `OpenClaw`
3. 安装项目 Python 依赖
4. 进入仓库根目录执行 `./scripts/fisco-up.sh`
5. 再启动你的 `FastAPI + 虚拟 App + 演示端`

最小系统要求：

- Docker 可用
- Java 可用
- Node 可用
- Python 3.12 可用

如果需要编译 `runtime-deps/java-sdk`，优先使用仓库内的 `JDK 11`：

```bash
export JAVA_HOME="$(pwd)/runtime-deps/jdks/temurin-11"
export PATH=$JAVA_HOME/bin:$PATH
cd runtime-deps/java-sdk
./gradlew classes -x test
```

## Windows

推荐方式不是原生直接跑，而是：

1. 安装 `Docker Desktop`
2. 开启 `WSL2`
3. 在 `WSL2 Ubuntu` 中放置这个仓库
4. 在 `WSL2` 内安装 `OpenClaw`、`Python` 依赖和 `Node`
5. 在 `WSL2` 内执行仓库脚本

这样可以避免 Windows 原生环境下路径、证书和 shell 行为不一致的问题。

## 边界说明

### 已解决的可迁移性问题

- FISCO 链配置和证书已纳入仓库
- FISCO Console 已纳入仓库
- FISCO Docker 镜像已导出到仓库
- 仓库提供统一启动、停止、状态检查脚本

### 仍然保留的外部依赖

- `OpenClaw` 仍需按官方方式安装
- Docker 仍需目标机器自行安装
- 当前脚本默认 Linux 或 WSL2 环境

### 不建议的方式

- 不建议再依赖宿主机上的 `/home/xxx/fisco` 临时目录
- 不建议把 VMware 虚拟机作为主交付形式
- 不建议在 Windows 原生命令行里直接跑整套脚本
